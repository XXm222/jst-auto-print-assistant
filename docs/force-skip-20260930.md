# 2026-09-30 强制跳过更新

客户端 V0.5.25 / API schema 5。

## 处理流程

1. 从最新问题任务确认内部订单号和出库单号。
2. 显示跳过原因并由操作员确认。
3. 停止当前执行线程。
4. 调用鉴权接口 `POST /jst-print-api/v1/order/force-skip`，请求字段为 `workstation_id`、`o_id`、`io_id`、`reason`。
5. 后台保存永久排除记录，客户端再更新本地状态为 `SKIPPED_OPERATOR` 并继续。

网络失败或后台未确认成功时，不将本地任务记为成功跳过，也不恢复执行。

## 后台数据与部署

`jst_lease_store.py` 自动创建 `operator_skips` 表，以 `(o_id, io_id)` 为联合主键，保存工作站、原因和时间。重复请求保留首次审计记录。`claim()` 在事务中检查永久排除记录，因此不受客户端 200 条排除上限影响。

强制跳过无需有效租约或打印完成证明。未完成的同一订单租约被关闭；已完成任务原有完成原因保留。此接口不会修改聚水潭订单状态。

部署前备份现有后台文件和 SQLite 数据库，替换后台 API、租约模块与匹配 planner。新建服务还需单独部署 ERP bridge，并在 `/etc/jst-print-api.env` 设置 token。使用 `server_batch_v056/jst-print-api.service` 作为模板。健康检查路径为 `/jst-print-api/health`，随后验证鉴权和 schema 5。

仓库后台还包含默认关闭的外部系统订单过滤功能。对旧生产服务部署时，应审阅完整差异，并协调客户端切换。

## 验证范围

新增及更新回归覆盖：所有暂停类型、RUNNING 状态、无租约、跨工作站、服务重启、超过 200 条、身份变化、后台失败、保留已完成证据及 HTTP 鉴权。
